Mullion

Catch agent regressions before they ship.

Compare a candidate agent with the one already in production, on the same scenarios. Mullion returns one suite status at 90% confidence: Pass, Block, Insufficient evidence, or Invalid run. Insufficient evidence can carry a A warning on insufficient evidence, not a separate status. Specification

The decision rules.

A One execution of one scenario. A pass scores 1. A fail scores 0. is one execution. Pass is 1. Fail is 0. The status applies to the suite. Repeated rollouts per arm. Scenarios are SHA-256 hashes.

90%

Confidence. Non-inferiority, δ = 5 pp. Pass when the lower bound is above −5 pp. Block when the upper bound is below −5 pp.

5%

Miss cap. Above this on either arm, the run is invalid. Exactly 5% still scores.

0.6

Coverage floor. Each scenario needs at least ceil(0.6 × scheduled) usable rollouts on both arms.

Paired

By scenario. Each one counts once. Order does not change the result.

Use cases

For founders and teams new to AI

An AI agent can change its behavior between versions even when the screens around it look the same. Moving from Gemini Flash-Lite to a newer Flash, a prompt edit, or a new tool can make yesterday's request fail today.

This check runs the version you are about to ship against the one customers already have, on the same tasks, and flags a drop larger than 5 points when the evidence is clear, and says when it can't tell yet. The check is provider-agnostic: Gemini comes first, and OpenAI and Anthropic are on the roadmap.

For ML and platform engineers

  • CI gate on the candidate versus the agent already in production.
  • Repeated rollouts, so one noisy try becomes a pass rate.
  • Non-inferiority, δ = 5 pp. Pass if the 90% interval's lower bound is above −5 pp, block if its upper bound is below −5 pp, otherwise insufficient evidence; an invalid run isn't scored.
  • Invalid-run detection when too many rollouts are missing or broken by infrastructure.

Gate behavior

Technical details

The adapter contract is provider-agnostic, and it is the intended seam. This repository does not ship an adapter. One rollout is one call: scenario id, SHA-256 of the scenario text, arm (baseline or candidate), and a step budget. The adapter returns pass, fail, agent timeout, or an infrastructure miss. An agent timeout scores 0. A provider error, a rate limit, or a killed runner is excluded from the score and counted toward the 5% miss cap. The model name does not enter the suite verdict.

First backend, in progress. The harness calls Gemini 3.5 Flash-Lite at the stable id gemini-3.5-flash-lite, the pin published 21 July 2026. That id is a specific stable model. The floating alias gemini-flash-latest is not the pin, because it moves. The adapter stays labeled in progress until it merges. OpenAI Agents SDK, Claude Agent SDK, LangGraph, LlamaIndex, CrewAI, AutoGen, and Microsoft Agent Framework are roadmap adapter examples, not backends in development, and not partnerships.

The scorer does not import an agent SDK. It pairs scenarios, builds the 90% interval, and the check fails on Block. Scenario rows stay diagnostics. They are not individual gates.

GitHub Action, planned. Trigger pull_request so the check can be required. The job runs both arms through the adapter and uploads results.json. It fails the check on Block. An invalid run is reported as invalid and isn't scored. A merge queue would also need the merge_group event. Buildkite, Jenkins, and your own runner are the same planned job, not separate products.

Record/replay cassettes, planned. Record mode would store model and tool traffic keyed by the scenario hash and the arm. Replay mode would return that recording and would not call the provider. A hash mismatch is a miss, not a silent reuse. A cassette is an input to scoring. It is not a verdict.

The output file is results.json version 1, or a 2.x.y string such as 2.0.0. Version 2.0.0 adds an optional one-sentence caption on a scenario or an arm. Decimals and amounts inside a caption are text. This page’s reader accepts those versions and rejects any other major version. promptfoo can also write a file named results.json. That file is a different contract.

OpenTelemetry GenAI spans, planned. If an agent already emits them, an adapter may attach the trace as a diagnostic. Spans do not set the suite status. Those semantic conventions are still marked Development. Inspect, promptfoo, LangSmith, Braintrust, and DeepEval are planned sources of scenarios or scores. They do not become the suite verdict.

FAQ

Operational questions.

What does Mullion decide?

Whether a candidate agent regressed relative to the one already running, before the change ships. The output is one suite status: Pass, Block, Insufficient evidence, or Invalid run. Scenarios are diagnostics, not individual gates.

What is a rollout?

One execution of one scenario. Pass scores 1. Fail scores 0. Scenarios are repeated because a single execution is not a stable estimate.

Why repeated rollouts?

Repeated rollouts per arm. Each scenario becomes a pass rate, then each scenario counts once. Additional rollouts do not add weight.

What does 90% confidence mean here?

Non-inferiority, δ = 5 pp. Pass if the 90% interval's lower bound is above −5 pp. Block if its upper bound is below −5 pp. Otherwise the result is insufficient evidence, which can carry a Likely regression warning. An invalid run isn't scored.

When is a run invalid?

When more than 5% of scheduled rollouts on either arm are missing or broken by infrastructure. Exactly 5% is still scored. Each scenario also needs at least 60% of its scheduled rollouts usable, rounded up. Repeated rollouts per arm.

Does a timeout count as a failure?

A loop or an exhausted step budget scores 0. A provider error, a rate limit, or a killed CI runner is excluded and counts toward the 5% miss cap.

Are the figures on this page customer results?

No. The results panel shows the bundled preliminary file. The console replays labeled sample configurations. Neither is a customer benchmark.

Which frameworks does it work with?

None are official integrations. The gate stays provider-agnostic. The first backend is Gemini 3.5 Flash-Lite, pinned to gemini-3.5-flash-lite, and that adapter is in progress until it merges. OpenAI Agents SDK, Claude Agent SDK, and the other framework names are roadmap adapter examples. The GitHub Action and the record/replay cassettes are planned. This page does read the results file.
