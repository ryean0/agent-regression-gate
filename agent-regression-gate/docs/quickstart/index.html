    Quickstart

    Five steps: add the workflow, add the adapter, allowlist the model, set the secret, open a PR. Anything not shipped yet is marked Planned.

    On this page

    1. Add the workflow
    2. Add the adapter
    3. Allowlist the model
    4. Set the secret
    5. Open a pull request

    Add the workflow Planned

    Add a workflow that runs on pull_request. The packaged Action that does this in one file is Planned. The shape below is the job: OIDC, no stored cloud key, and a read-only pull-request role.

    workflow.yml · Planned

    name: anubys
on:
  pull_request:
permissions:
  contents: read
  id-token: write
  pull-requests: read
jobs:
  gate:
    name: Anubys
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      # Planned: a packaged Action, one file.
      # The job requests an OIDC token.
      # It does not store a cloud key.

    The CI reference is the same contract. workflow_dispatch on a pull-request branch does not satisfy a required check.

    Add the adapter Built

    Add the adapter. Gemini is the reference: one adapter, and one allowlist entry. The adapter runs a scenario and returns one outcome. It does not decide the suite status.

    adapter.yml

    adapter: gemini
allow:
  - gemini-3.5-flash-lite

    The contract is on the adapter reference. A second provider is Planned.

    Allowlist the model Built

    Allowlist the model id the adapter may call. The shipped entry is gemini-3.5-flash-lite, the stable id for Gemini 3.5 Flash-Lite. A floating alias is not the pin.

    OpenAI and Anthropic are not on the allowlist. That second provider is Planned.

    Set the secret Built

    Set the secret is the keyless step. Do not store a cloud key on the repository. The workflow asks GitHub for an OIDC token. The role it assumes can read the pull request and cannot write it.

    That path is Built. A long-lived cloud key is not part of the setup. Keyless CI, spend governance, and the audit trail are Built. Data stays in your cloud is Planned.

    Open a pull request Planned

    Open a PR. The check is meant to run on that event and post one suite status. Requiring the check waits on the packaged Action, which is Planned.

    This site already reads the results file that job is meant to upload. Replace that file in place when a real run is ready. The page does not change.
