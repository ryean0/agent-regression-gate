    Schema 1

    Schema 1 is the original results file. This page reads it. The file carries version, status, level, likely_regression, and arms. status is preliminary or final. level is 0.9.

    likely_regression false is Pass. True is Block. Null, when the run is not invalid, is Insufficient evidence. invalid_run true is Invalid run.

    Schema 2.0.0

    Schema 2.0.0 adds an optional one-sentence caption on each scenario and arm, and an optional model_id on each arm. This page still reads 2.0.0. A model id is shown when it is present and does not change the suite status. The shipped sample is 2.1.0.

    results.json · 2.0.0

    {
  "version": "2.0.0",
  "status": "preliminary",
  "level": 0.9,
  "likely_regression": false,
  "invalid_run": false,
  "arms": {
    "baseline": {
      "scheduled_rollouts": 8,
      "environment_misses": 0,
      "miss_counts": {},
      "model_id": "gemini-3.5-flash-lite"
    },
    "candidate": {
      "scheduled_rollouts": 8,
      "environment_misses": 0,
      "miss_counts": {},
      "model_id": "gemini-3.5-flash-lite"
    }
  }
}

    Schema 2.1.0

    Schema 2.1.0 is the file this page reads, along with schema 1 and 2.0.0. It adds schema_version, verdicts.overall.model_ids for the baseline and the candidate, and optional gate settings: delta, alpha, min_valid, ci_level, and miss_cap. Overall model ids are preferred over the per-arm model_id when they are present. Gate settings are display-only. When they are missing the page shows δ = 5 pp / 90%. They do not change the suite status.

    results.json · 2.1.0

    {
  "version": "2.1.0",
  "schema_version": "2.1.0",
  "verdicts": {
    "overall": {
      "model_ids": {
        "baseline": "gemini-2.5-flash-lite-001",
        "candidate": "gemini-3.5-flash-lite"
      }
    }
  },
  "gate": { "delta": "0.05", "ci_level": "0.9", "miss_cap": "0.05" }
}

    Still in progress, and not part of this 2.1.0 reader: a per-family estimate and interval, cost per verdict, and the MDE on the check. A family row has no verdict. The gate stays on the pooled result. Those fields are Next, in Wk4.

    Reproducible audit trail Built

    The results file is the reproducible audit trail. It records the schema version, the suite status, both arms, and the scenario hash. A later review can read the same file and reach the same status.

    That trail is Built. Where the file is stored is separate: results currently go to an S3 bucket the team controls. Data stays in your cloud is Planned.
