    Getting started

    This page is for someone who wants to try Anubys on their own computer. You do not need to know how to write a program. Plan on about 20 minutes. The free parts need no API key and no money.

    On this page

    1. What Anubys does
    2. Before you start
    3. Install Anubys
    4. Sample use cases
    5. Glossary

    Anubys is free and open source, under the MIT license. The program you type is called harness. The project folder is named ci-agent-regression-harness. Both of those names mean Anubys.

    The same steps are in docs/GETTING_STARTED.md (beta testing). That file is the canonical source. These checks are also listed on the use cases page.

    What Anubys does

    Anubys compares a new version of an AI agent with the version you already trust. You give it scenarios, which are practice tasks with a known shape. It runs the The agent you already trust. (the trusted agent) and the The new agent you are considering. (the new agent) on those same tasks. The comparison ends as one verdict.

    text

    your agent -> scenarios -> baseline vs candidate -> one verdict

  Pass
  Block
  Insufficient evidence
  Invalid run

    Those are the only four verdicts. In files they are spelled pass, block, insufficient_evidence, and invalid_run.

    The sentences in this table are the ones stored on the sample results file.
    VerdictIn plain words
    Pass The new agent was close enough to the current one that this test says go ahead.
    Block The new agent was clearly worse than the current one, so this test says stop.
    Insufficient evidence This test cannot yet tell whether the new agent is close enough, so it is not a yes or a no.
    Invalid run The test run itself was not reliable, so this result should not be used to decide.

    The check a results file section prints them from that file. Suite scoring, statistics, and report rendering are still placeholders. There is no command on this page that compares two live agents.

    Before you start

    What you need

    • A computer running macOS, Windows, or Linux.
    • About 20 minutes.
    • Python 3.11 or newer. Python 3.12 is fine. Python 3.10 is too old.
    • Git, the tool that downloads the project folder.
    • No API key for the free sections below.
    • No money for the free sections below.

    Windows PowerShell can run every command in this guide. You do not need Windows Subsystem for Linux (WSL).

    Use the left and right arrow keys to change the computer. Home and End jump to the first and last choice.

    Showing steps for macOS.

    Open a A window where you type one line, press Enter, and read the reply.

    A terminal is a window where you type one line, press Enter, and read the reply.

    macOS

    Open Spotlight (Command and the space bar), type Terminal, and press Return. You can also open Applications, then Utilities, then Terminal.

    Windows (PowerShell)

    Open the Start menu, type PowerShell, and open Windows PowerShell. Leave WSL uninstalled unless you already use it for something else.

    Linux

    Open the app named Terminal, or the terminal that came with your desktop.

    The examples below use that window. Type each command yourself. Press Enter at the end of the line.

    Install Python 3.11 or newer

    Check what you already have before you download anything.

    macOS

    This prints the Python 3 version, if Python 3 is installed.

    shell

    python3 --version

    Windows (PowerShell)

    This prints the Python version the python command points at.

    PowerShell

    python --version

    Linux

    This prints the Python 3 version, if Python 3 is installed.

    shell

    python3 --version

    You want a line that starts with Python 3.11 or a newer 3.x, such as Python 3.12. If you see that, skip the installer and go to Install Git.

    If the command is missing, or the version is older than 3.11, install Python from the official site: https://www.python.org/downloads/. Pick the latest Python 3 release. It will be 3.11 or newer.

    macOS

    Run the downloaded installer, then open a new Terminal window.

    Windows (PowerShell)

    Run the downloaded installer. On the first screen, check the box Add python.exe to PATH. Then finish the install. Close the terminal window and open a new PowerShell window so it can see Python.

    Linux

    If python3 --version is already 3.11 or newer, keep that Python. Use the python.org installer only when the version is missing or too old.

    Install Git

    Check Git next. This prints the Git version. Any current version is fine. If you see a version number, skip the Git installer.

    shell

    git --version

    If Git is missing, download it from https://git-scm.com/downloads.

    macOS

    The git-scm installer works. The first time you type git, macOS may also offer the Xcode command line tools. Either path is fine.

    Windows (PowerShell)

    Install Git for Windows and accept the default options. This does not install WSL. Close PowerShell and open it again afterward.

    Linux

    Install the git package from your system, or use the git-scm installer. Many Linux systems already have Git.

    Check the versions

    Run the version commands again in a new terminal window.

    macOS

    You want python3 --version to show 3.11 or newer, and git --version to show a version.

    Windows (PowerShell)

    python --version and git --version do the same jobs.

    Linux

    You want python3 --version to show 3.11 or newer, and git --version to show a version.

    This guide was checked on Linux with Python 3.11.17 and Git 2.43.0. Your patch numbers can be newer. The Python major.minor version needs to be 3.11 or newer.

    If you see this error

    These are the failures that showed up while checking the install. The quoted lines are real messages from those checks.

    Python is not found. A shell with no python command printed:

    output

    python: command not found

    On macOS and Linux, use python3 until the virtual environment is on. After that, python works. On Windows, the same problem means the installer is missing or the Add python.exe to PATH box was unchecked. Run the installer again, choose Modify, check that box, then open a new PowerShell window.

    The tool that installs Python packages. This guide uses python -m pip so the pip command itself does not have to be on your PATH. is not found. python -m pip in a Python that was built without pip printed:

    output

    No module named pip

    A normal install from python.org includes pip, and a virtual environment includes it too. Re-run the Python installer. On Windows, choose Modify and include pip. In this guide, install packages with python -m pip so the pip command itself does not have to be on your PATH.

    Permission errors. Creating a virtual environment in a folder the computer will not let you write printed:

    output

    Error: [Errno 13] Permission denied: '/tmp/noperm/venv'

    Create the project folder inside your home folder, somewhere your user can write, and run the commands there.

    Installing with the system Python, outside a virtual environment, printed:

    output

    Defaulting to user installation because normal site-packages is not writeable

    That means the command missed the virtual environment. Turn the environment on (see below), then run the install again.

    The Python version is too old. Installing Anubys with Python 3.10.22 printed:

    output

    ERROR: Package 'ci-agent-regression-harness' requires a different Python: 3.10.22 not in '>=3.11'

    The 3.10.22 piece is the old Python that was tried. Yours may show a different old number. Install Python 3.11 or newer, open a new terminal, and create the virtual environment with that Python.

    Install Anubys

    There is no pip install anubys package on the public Python package index. Use one of the two options below.

    A A private folder of Python packages for this project, so the install does not change the Python used by the rest of your computer. is a private folder of Python packages for this project, so the install does not change the Python used by the rest of your computer.

    The sample tasks later on this page live in the project folder. Option B downloads that folder. Option A installs the program only.

    Turn on a virtual environment

    From the folder where you want the private environment (for Option B, that is the project folder):

    macOS

    This creates a hidden folder named .venv.

    shell

    python3 -m venv .venv

    This points the word python at that folder for this terminal.

    shell

    source .venv/bin/activate

    Windows (PowerShell)

    This creates the same .venv folder.

    PowerShell

    python -m venv .venv

    This turns the environment on in PowerShell.

    PowerShell

    .venv\Scripts\Activate.ps1

    If PowerShell will not run that script, skip activation and call the environment's Python by name.

    PowerShell

    .venv\Scripts\python.exe -m pip install --require-hashes -r requirements.lock

    This downloads the locked libraries with the private Python.

    PowerShell

    .venv\Scripts\python.exe -m pip install --no-deps -e .

    This installs Anubys from the project folder with the private Python.

    Linux

    This creates a hidden folder named .venv.

    shell

    python3 -m venv .venv

    This points the word python at that folder for this terminal.

    shell

    source .venv/bin/activate

    After activation, check Python again. This prints the Python inside the environment. It should be 3.11 or newer. On the check for this page it printed Python 3.11.17.

    shell

    python --version

    A notice that a newer pip exists can be ignored. The install still works.

    Option A. Install the program from GitHub

    Use this once your computer can read the repository. After the repository is public, that includes everyone. From a terminal where the virtual environment is on:

    shell · (beta testing)

    python -m pip install "git+https://github.com/rphua-dev/ci-agent-regression-harness"

    This downloads Anubys from GitHub and installs the harness program. Pip picks library versions inside the ranges the project allows. Option B, below, is the one that installs the locked hashes.

    The command was run in a fresh Python 3.11 virtual environment. It finished by installing ci-agent-regression-harness version 0.0.1. Then:

    shell

    python -m harness --help

    This lists the commands the program accepts. The check printed these names: validate, export-schema, convert-tau-retail, hash, gates, build-mvp-families, and validate-results.

    Option A does not put the sample scenarios in the folder you are standing in. Running a sample from the wrong folder prints a line like this (the path will be whatever folder you used):

    output

    /tmp/does-not-exist-scenarios: path does not exist
1 error(s) in 0 file(s); 0 scenario(s) parsed

    The samples in the next section need Option B, because they read files that ship in the repository.

    Option B. Download the repository and install the pinned versions

    This is the setup the project contributors use, and it is the one the samples need. In a folder where you keep projects:

    shell · (beta testing)

    git clone https://github.com/rphua-dev/ci-agent-regression-harness.git

    This downloads the project. The check printed Cloning into 'ci-agent-regression-harness'... and left a folder of that name.

    shell

    cd ci-agent-regression-harness

    This moves into the project folder. You are in the right place when that folder contains a file named requirements.lock.

    Create and turn on the virtual environment, as in Turn on a virtual environment. Then:

    shell

    python -m pip install --require-hashes -r requirements.lock

    This downloads the exact library versions locked for this project and checks each file's hash. It can take a few minutes. It is done when the last line says Successfully installed and lists the libraries.

    shell

    python -m pip install --no-deps -e .

    This installs Anubys from the folder you are in, and it reuses the libraries from the line above. The -e means Python reads this folder when you run harness. The check ended with:

    output

    Successfully installed ci-agent-regression-harness-0.0.1

    If the clone fails because GitHub will not show you the repository, the project is still private. Wait until it is public, or use a copy someone has already shared with you. Then start at cd into that copy and run the two python -m pip lines.

    Sample use cases

    Run these from the project folder, with the virtual environment on. The free commands before the live-model section were run on Python 3.11 with GEMINI_API_KEY unset. They do not call a model, and they do not spend money.

    python -m harness runs the program even if the harness command is not on your PATH. After Option B, harness and python -m harness do the same job. The samples use python -m harness.

    Check that the example scenarios are valid

    You want to know that the small set of example shopping tasks is written in the shape Anubys accepts.

    shell

    python -m harness validate suites/tau_retail/examples

    This reads the example files and checks their shape. It does not run an agent.

    You should see

    output

    ok 9 scenario(s), 0 suite file(s)

    That means all 9 example files are valid.

    The same check covers the larger retail folder and its suite file:

    shell

    python -m harness validate suites/tau_retail

    This walks the whole retail suite, including the examples and the scenario set used by the safety checks.

    You should see

    output

    ok 87 scenario(s), 1 suite file(s)

    That means 87 scenario files and 1 suite file passed. The 9 example files and the 78 files in the scenarios folder are those 87.

    More detail on the file shape is in scenario-format.md (beta testing).

    Run the safety checks

    You want to know the sanitized scenarios are safe to keep: the shape is valid, the personal data is synthetic, there are no secrets, and the tasks are not copies of each other.

    shell

    python -m harness gates suites/tau_retail/scenarios

    This runs six safety checks on the scenarios folder. It does not call a model. Gitleaks, an optional extra secret scanner, is not required on your own computer.

    You should see

    output

    schema: pass (78 scenario(s), 0 suite file(s))
synthetic-pii: pass (78 scenario(s), 0 cassette file(s))
secrets: pass (python scanner; gitleaks not installed, trufflehog not installed; 78 file(s))
exact-duplicates: pass (78 scenario(s), canonical content hash)
near-duplicates: pass (78 scenario(s), MinHash on user turns, threshold 0.8)
splits: pass (26 family(ies), one split each)
ok 6 gate(s)

    ok 6 gate(s) means every check passed. gitleaks not installed and trufflehog not installed are normal on a laptop. The secrets line still says pass. The project's CI installs gitleaks and adds --require-gitleaks. You can leave that flag off.

    Point this command at suites/tau_retail/scenarios only. The examples folder is a straight conversion and still has upstream personal data, so the synthetic-data check is supposed to reject it. A check of that folder ended with 1 gate(s) failed: synthetic-pii. That failure is expected there. Use validate for the examples, and gates for suites/tau_retail/scenarios.

    Check a results file and read its verdict

    You have a results file and you want the verdict in plain words. The file in the repository is practice data for a demo page. It is not a score from a real agent.

    shell

    python -m harness validate-results docs/examples/results.preliminary.json

    This checks that the results file has the fields Anubys expects. It does not print the verdict.

    You should see

    output

    ok 1 results file(s)

    That means the file is valid. Read the verdict with:

    shell

    python -c "import json; doc=json.load(open('docs/examples/results.preliminary.json', encoding='utf-8')); labels=doc['verdicts']['verdict_captions']; print(doc['verdicts']['overall']['verdict']); print(doc['note']); print('pass:', labels['pass']['caption']); print('block:', labels['block']['caption']); print('insufficient_evidence:', labels['insufficient_evidence']['caption']); print('invalid_run:', labels['invalid_run']['caption'])"

    This opens the sample file and prints the verdict word, the note, and one sentence for each of the four verdicts.

    You should see

    output

    insufficient_evidence
FAKE preliminary data for the demo landing page. Not a baseline and not a gate result.
pass: The new agent was close enough to the current one that this test says go ahead.
block: The new agent was clearly worse than the current one, so this test says stop.
insufficient_evidence: This test cannot yet tell whether the new agent is close enough, so it is not a yes or a no.
invalid_run: The test run itself was not reliable, so this result should not be used to decide.

    The verdict on this file is Insufficient evidence: the test cannot yet say yes or no. The second line says the numbers are fake, so do not treat them as a real comparison. The field guide for the file is results-format.md (beta testing).

    Preview converting tau-bench retail tasks

    You want a preview of how the vendored tau-bench retail tasks would be classified, without writing files and without spending money.

    shell

    python -m harness convert-tau-retail --dry-run

    This counts the local retail tasks on the test split and prints three policy labels. --dry-run writes nothing. The tasks are already in the repository, so this does not download them and does not call a model.

    You should see

    output

    split test: 115 tasks
  allowed: 104
  must_refuse: 7
  ambiguous: 4

    That means the test split has 115 tasks: 104 the agent may carry out, 7 the agent must refuse, and 4 that are ambiguous. 115 is the original tau-bench task list. 87 is the number of Anubys's converted scenarios. No scenario files were written. Stop here for the preview. Adding --out would write files, and this page does not ask you to do that.

    Run against a real model (costs money)

    Costs money

    A live run sends tasks to Google Gemini and can charge the Google account that owns the API key. Read this section so you know how the guard rails work. Do not start a live run from this page.

    There is no tiny live command on main. python -m harness --help has no command that calls Gemini. The manual workflow file .github/workflows/experiment.yml is still a placeholder. Its last step says that no Gemini call was made. Do not run that workflow as if it were a live test, and do not paste a workflow into your repository from this page.

    When a real live command exists, it will be a labeled experiment. Until then, the steps below only prepare a key and show the free spend check.

    Get a Gemini API key

    1. Sign in to Google AI Studio.
    2. Open the API keys page and create a key. Google's steps are in the Gemini API key guide.
    3. Copy the key once. Keep it in the terminal only.

    Keep the key out of the project

    Paste the key only into the current terminal, never into a file you could commit. Do not put it in a scenario, in spend/spend_log.jsonl, or in a note.

    macOS

    In the same terminal where the virtual environment is on, this holds the key in that terminal until you close the window.

    shell · placeholder

    export GEMINI_API_KEY="paste-the-key-here"

    Windows (PowerShell)

    This does the same thing in PowerShell.

    PowerShell · placeholder

    $env:GEMINI_API_KEY = "paste-the-key-here"

    Linux

    In the same terminal where the virtual environment is on, this holds the key in that terminal until you close the window.

    shell · placeholder

    export GEMINI_API_KEY="paste-the-key-here"

    Check that the key is present without printing it. This prints set when the variable has a key, and missing when it does not. It does not print the key.

    shell

    python -c "import os; print('set' if os.environ.get('GEMINI_API_KEY','').strip() else 'missing')"

    With no key, which is how every free command on this page was run, you should see:

    output

    missing

    Spend safety

    Two checks sit in front of a live rollout.

    Per-rollout dollar limit. A live rollout can be given a dollar ceiling. If the model cost of that one rollout is above the ceiling, Anubys marks it with the reason spend_ceiling. Going over that limit counts as a fail, not a miss. That is the agreed policy, and it lands in an upcoming pull request. The cost is still written to the spend log. The suite can continue with the next rollout. Only the monthly Example $38 stop counts as a miss.

    The Example $38 monthly check. Anubys adds up spend/spend_log.jsonl for the current calendar month in UTC. Once that logged total reaches Example $38, Anubys does not start another live rollout. Before it starts one, it also adds what the next rollout is allowed to cost: your per-rollout ceiling, or the cost of the previous logged row when no ceiling is set. If that sum would reach Example $38, the next rollout does not start. A rollout that has already started is allowed to finish, so the logged total can end a little above Example $38.

    A budget alert in Google's own console does not stop the calls. The monthly check is what stops new live rollouts, and a small overshoot is possible.

    You can run the monthly check itself for free. It only reads the log. This sums the log for the current UTC month and compares it with Example $38. It does not call a model.

    shell

    python scripts/check_monthly_spend.py --threshold 38

    The check on 16 October 2026 printed:

    output

    Example

    2026-10 logged spend is $0, under the $38 cap.

    Your line can start with a later month, such as the month you run it. Example $0 means the log has no spend in that month. The log file in the repository is empty until a labeled experiment appends a row. Leave the file alone.

    Glossary

    Scenario. One practice task: a customer situation, the tools the agent may use, and the checks Anubys applies to the outcome.

    Baseline. The agent you already trust. Anubys compares the new agent against it.

    Candidate. The new agent you are considering.

    Verdict. The single decision for a comparison. It is Pass, Block, Insufficient evidence, or Invalid run.

    Rollout. One try of one scenario by one agent. A live rollout can call a model. The free commands on this page do not run rollouts.

    Sanitization gates. The six safety checks in python -m harness gates: file shape, synthetic personal data, secrets, exact copies, near copies, and one split per family.

    Virtual environment. A private folder of Python packages for this project, usually named .venv.

    Spend log. The file spend/spend_log.jsonl, an append-only list of what live runs cost. Replay of a model recording writes a Example $0 row. The monthly check reads this file.

    Cassette. A saved recording of a previous run. The code can replay one. There is no harness command for that yet.

    tau-bench retail. A public set of shopping support tasks. This repository already contains a copy. convert-tau-retail --dry-run only counts that local copy.

    Getting help

    Open an issue on the repository: https://github.com/rphua-dev/ci-agent-regression-harness/issues (beta testing).

    Include the command you ran, the full output, and the output of python --version. Say whether you are on macOS, Windows, or Linux. Remove any line that contains your API key before you post.

    If GitHub says you cannot see the repository, it is not public yet.

    The contributor checks (lint and tests) are listed in CONTRIBUTING.md (beta testing). The spend log rules are in spend/README.md (beta testing).
